# 阶段 P13：合成语料真实模型端到端验收

日期：2026-10-20

## 目标

P11 的真实论文评测显示页面命中与回答覆盖不足。不能把私人毕设文献发给云模型，也不能用修过的同一题集证明泛化。本阶段用固定的公开于仓库的合成 PDF，单独检查 BM25、模型筛选、生成、claim 审查、页码引用与拒答。

## 执行链路

```text
合成 PDF A/B
  -> PyMuPDF 页级解析
  -> SQLite FTS5 索引
  -> BM25 候选摘录
  -> DeepSeek 证据筛选
  -> 结构化原子 claims
  -> 逐 claim 支持审查与覆盖审查
  -> PDF SHA-256、物理页码和原文核验
  -> 保留原始轨迹和评测摘要
```

模型运行前，先把 6 题 gold 和两份 PDF 的 SHA-256 写入 manifest 并提交。Gold 引文独立指向 5 处原文。`scripts/build_p12_synthetic.py` 重建隔离的 `.local/p12-synthetic` 数据库，不改动用户文献索引。

## 结果

模型运行 17 次 DeepSeek Flash API 请求。4 道可答题全部有完整回答，引用覆盖全部 gold 页；9 条 claims 全部通过支持审查。2 道应拒答题均拒答。总费用峰时上界 `$0.0030273`；合并后项目累计上界 `$0.2579835 / $0.50`。

摘录模式也能命中 4/4 可答题，但其中一道应拒答题返回了与“区域最慢”相关、却不能回答该问题的原文摘录。摘录 UI 已明确声明不综合其含义；模型审查模式则正确拒答。指标和每题输出见[评测报告](../../reports/p12-synthetic-20261020.md)及机器可读[原始结果](../../reports/p12-synthetic-20261020.json)。

## 统计边界

6 题过少，且只有英文合成 PDF、一个跨论文问题和一次模型运行。即使本次是 6/6，也不能推断生产准确率。P11 毕设语料上页面 gold 命中仍只有 3/5；本阶段没有用 DeepSeek 重测或读取私人文献。向量检索集成测试因缺少 `scikit-learn` 未纳入本机 37 项回归，需在完整开发依赖环境重新运行全套测试。

## 面试追问

**6/6 能证明什么？**

只能证明当前冻结的 6 个合成问题在这一次配置下通过。它不是可靠率估计，也不是生产数据测试。

**为什么摘录模式与生成模式都保留？**

摘录模式不综合文本，可在本机不依赖生成模型时提供原文定位；生成模式提供便于阅读的答案，但增加模型成本和审查路径。两种模式都保留页码与原文核验。

**为什么不能说解决了 P11 的问题？**

P11 的问题来自私人论文检索，当前测试只用新建的合成 PDF。没有证据证明相同修复能提升真实论文召回。
