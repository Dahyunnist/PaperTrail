# P10：复杂问题覆盖与交付复验

## 目标与实现

P10 在 P9 之后增加了一轮有界的问答质量复验。复杂问题会先拆成最多 4 个子问题，再分别检索；答案可保留有证据支持的部分，并标出未覆盖项。综合输出预算提高到 800 tokens。生成返回空 claims 时只做一次短重试，引用与逐 claim 支持审查规则不变。Web 支持通过环境变量设置检索模式和证据条数，默认仍是 BM25 与 5 条证据。

12 道小型非盲留出题先冻结，再进行一次真实模型运行。题集含 11 道可回答题和 1 道不可回答题，覆盖事实定位、方法比较、跨论文、多跳及指标冲突；20 条短引文全部通过 PDF SHA-256、页码和原文验证。题集与 P9 分开保存，不称为盲测，也不合并统计。

## 结果

DeepSeek `deepseek-flash` 在 `hybrid_bge_wide`、每题 8 条证据配置下完成一次真实评测，共 23 次 API 请求，输入 11,074 tokens、输出 8,452 tokens，费用上界 `$0.0134646`。累计账本为 `$0.2255514 / $0.50`。

人工逐题审阅结果：1 题正确、0 题部分正确、1 题错误、10 题拒答。11 道可回答题中，1 道回答正确，1 道给出错误的证据覆盖判断，9 道错误拒答；不可回答题正确拒答 1/1。唯一完整正确回答是 CoMedBench 任务数差异与占比的多跳计算，5 条引用原文均有效。ECE 题虽返回部分答案状态，但把摘要中明确写出的关系判为“未说明”，人工计为错误。

问答轨迹显示 5 次综合输出因 `finish_reason=length` 截断，2 题触发空 claims 定向重试。跨论文和冲突题仍大多拒答。子问题规划、较高输出预算与一次重试没有带来足够质量增益；按本阶段门槛停止后续调参，不从这一小样本推断泛化或生产质量。

## 验证与演示

- 全仓测试：32 passed。
- P10 黄金集：12 题，20 条引文全部通过原文校验。
- Web：本机页面返回 HTTP 200；浏览器显示本地文献工作台，索引出 65 个文献版本及问答、跨论文对照和笔记入口。
- 原始运行结果保存在忽略文件 `.local/p10-final.json`；逐题人工审阅保存在 `evals/p10-human-review-20261020.json`。

## 学习与边界

增大生成预算解决不了检索到的页面缺少关键细节、引用格式无效、证据组织失败或模型在结构化输出中的截断。规划器能拆题，但多子问题会扩大输出长度与审查负担。后续应先提升页级证据组织和可预测的结构输出，再用新的冻结题集验证；不得在 P10 留出题上继续调参后仍把它当作未触碰评测集。

P9 的 30 题结果仍单独记录。P10 仅提供小样本失败诊断，不代表 P9 改善，也不支持完整覆盖或生产级能力声明。
