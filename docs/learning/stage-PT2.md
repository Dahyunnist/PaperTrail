# PT2：解析、检索与证据覆盖

日期：2026-10-23

## 诊断与改动

原 PDF 解析依赖 PyMuPDF 的垂直排序。双栏段落在相近纵坐标时可能左右交错，导致章节上下文和检索块顺序错误。新增保守的双栏识别：仅当页面左右各有多个稳定文本块、横跨栏的锚点较少时，按左栏再右栏排序；全宽标题保留在对应纵向位置。不能稳定识别的页面保留原顺序。原文块仍按页保存，不把跨页文本合成无法单页核验的引用。

复核还发现，托管提示长度压缩原先从末尾删除证据，会静默删去子问题唯一的证据槽。现在只先删除仍有重复槽覆盖的候选；否则优先缩短最长摘录。最低压缩后仍不能满足长度上限时明确报错，不悄悄丢掉唯一槽。复杂问题已有逐子问题检索和候选扩展；本阶段没有改变排序策略或引用门槛。

新增双栏排序和槽保留回归测试。离线复现脚本 `scripts/evaluate_pt1_local.py` 读取本地冻结集和本地索引，报告页级召回、MRR、候选页精度、完整引文集合覆盖和延迟。输出只含题目 ID 与指标，不含问题、引文、路径或全文。

```powershell
python scripts/evaluate_pt1_local.py
```

## 冻结开发集结果

使用 8 道 PT1 开发题、单篇真实论文和既有本地索引；不重建原数据库、不调用模型 API。向量索引写入新的忽略文件 `.local/pt1-expanded-vectors.joblib`。结果保存为 `.local/pt2-real-retrieval.json`。

| 模式 | Recall@5 | MRR@5 | 完整目标页 / 8 | 候选页精度@5 | 完整引文集合 / 8 | 延迟中位数@5 |
|---|---:|---:|---:|---:|---:|---:|
| BM25 | 1.000 | 0.813 | 8/8 | 0.250 | 4/8 | 76 ms |
| 字符 TF-IDF + SVD 向量 | 0.250 | 0.188 | 2/8 | 0.073 | 1/8 | 101 ms |
| BM25 + 向量 RRF | 0.875 | 0.588 | 7/8 | 0.194 | 4/8 | 669 ms |

Recall@10 分别为 1.000、0.250、1.000；完整引文集合均为 4/8。页级命中不能代表证据完整：BM25 找到全部目标页，但 4 道题仍未检索到每个最小引文。需答案枚举多个独立要点的题目 PT1-02、PT1-03、PT1-04、PT1-05 有缺项。候选页精度统计的是 top-k 不重复 PDF 页中属于 gold 页的比例，不是最终答案引文准确率。

P9 历史报告显示本机 CrossEncoder 权重缺失；本次运行环境也没有可用 `sentence_transformers`，所以 BGE 与 CrossEncoder 重排未跑。离线对照只能比较 BM25、字符向量和 RRF。此小样本不支持改变默认检索模式；BM25 在本集优于向量与 RRF。

## 历史问答边界与结果

旧 P12 是真实私有语料上的 6 题非盲诊断，结果不一致：三次历史模型结果的完整覆盖分别为 0.8、0.4、0.8；目标页命中率分别为 0.8、0.2、0.6。不可回答题也曾出现一次错误作答。三次运行共用旧模型账本与同一小型题集；不重跑、不合并，也不把这些数字称为 PT1 的新基线。

本阶段没有把私有文献、问题或摘录发送到云端，因此没有新的问答 token、API 延迟或费用。离线检索时延不等于完整 RAG 回答时延。真实集只有一个开发论文，没有跨论文、冲突或拒答题；这些能力留待新的合成 PT3 夹具验证。
