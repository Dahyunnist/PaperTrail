# PT4：版本对账、索引失效与许可登记

日期：2026-10-23

## 来源版本与增量恢复

`paper_versions.version_id` 仍由源 PDF 的 SHA-256 确定，解析版本另存于 `parser_version`。配置目录的“索引已选来源”现在把所选清单视为这些配置 root 的完整快照：清单遗漏或文件删除会清除旧位置；同一路径哈希变化会解绑旧版本并索引新版本。重复运行不改索引修订号；新增、替换、删除会递增修订号，供向量索引识别过期。源文件从不由对账操作删除。

清单先整体解析和校验，再做对账。逐篇写入在 SQLite 事务内执行；崩溃后同一清单可重放。后台任务仍按原队列恢复。个人上传采用独立单文件任务，不把它误当成上传目录的完整快照。上传删除只删应用管理目录内文件；共享哈希版本在仍有其他来源位置时保留。

离线验证新增临时数据库用例，覆盖同清单幂等、路径内容替换、删除失效和修订号变化。完整 pytest 未能启动：当前运行时没有 pytest，也没有项目依赖（如 PyMuPDF）；未联网安装依赖。

## Web 与权限边界

文献列表显示内容版本 ID 与哈希。已保存回答显示 claim、原文引句、物理 PDF 页、版本 ID；保存覆盖缺项，可区分有缺项与未记录缺项。

应用与 MCP 服务均使用一个 `PAPERTRAIL_DB`，没有账户、集合或多租户授权模型。因此不存在可声称通过的跨用户 ACL 测试；MCP 只读访问所选本地数据库，并按 SHA、页码和源文件哈希验证直接证据。当前范围明确为单用户本地运行。

## API 与隐私

PT4 不调用模型。未读取或提交本机论文路径、私有 PDF、题目、摘录或忽略目录内容。
