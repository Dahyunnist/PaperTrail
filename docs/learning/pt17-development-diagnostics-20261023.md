# PT17 开发集逐题损失诊断

PT17 已转为已见开发集。原始单次结果、金标、来源 PDF 和哈希均保留；本诊断不调用模型、不重跑 holdout。

## 语料解析

3 篇官方 PDF 均成功解析：3 个版本、111 个章节、469 个片段，无低文本文档。7 条金标证据均在预登记时通过 PDF 页码、哈希和原文校验。解析不是 PT17 本次主要损失点。

## 根因

`_candidate_excerpt` 用完全相同 token 的交集给句子排序，再按 200 字 hosted 摘录上限截断。PT17-01 的问题句因匹配 `external/package/versions` 得分较高，排在提供处置建议的下一句之前；筛选器看不到支持答案的句子。PT17-02 还存在跨表达：题目写 `models/datasets/reuse`，原文用 `model weights/training data/share` 与 `persistent identifier`。候选页召回了，却没把关键句暴露给筛选器。

同模型覆盖审查对 PT17-01/02 标记为 partial，因此没有完整答案放行；支持/引文门槛仍有效。预算硬门禁又中断最后 3 题。原始报告把 PT17-04 的 `status=abstained` 算成成功拒答，是评分器把预算中断与语义拒答混为一谈；更正后有效不可答拒答仍为 `0/1`。

## 最小改动候选

不放宽支持或引用校验。只改筛选器看到的候选摘录排序：对“recommend/should/how”类行动问题，用已有模糊词形匹配，并优先保留建议、操作类原句；仍只发送来源原文。增加测试，证明问题不会挤掉解决建议，同时保留跨来源拆解、partial 和不可答拒答回归。预算拦截另以 `completion_state` 标明，避免统计时误作正确拒答。

## 开发修复与离线回归

完成最小摘录排序修复：行动问题提高建议句优先级；询问文件形式时提高“common forms/formats/types”句优先级。PT17 原文离线核对中，PT17-01/02/03/05 的所有 7 个金标证据槽均出现在候选摘录内；筛选及引用质量仍需独立盲集模型评测确认。

加入预算截停与语义拒答的独立状态；评分器只把 `refused` 或 `no_evidence` 计为正确拒答。离线回归覆盖跨来源问题拆解、partial 回答、不可答拒答、预算截停以及候选摘录问题句和建议句竞争。全套测试：70 passed。未调用模型。
