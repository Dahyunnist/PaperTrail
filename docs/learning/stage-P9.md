## 答题修复

P8 的 24 次错误拒答按证据路径拆分：2 次检索结果没有目标页，11 次检索含目标页但最终证据摘录未含目标页，11 次目标页已进入证据仍未回答。旧轨迹的拒答正文有 20 次生成/审查拒答、4 次无证据拒答；缺少原始 claim 记录，不能细分 claim 判定与覆盖拒绝。

代码修复包括：

- 将 hosted 证据筛选扩为最多 12 个候选页，缩短候选摘录以控制请求长度。
- 以文献版本哈希分别限制每篇论文的摘录数，保留同题不同版本的对照证据。
- 保留通过支持审查的部分 claims，并明确显示“部分回答”。
- 覆盖审查要求逐项列出必答要点与缺项；枚举题必须保留原文中的具体算法名和执行方式。
- 将拒答原因、候选/证据页数、覆盖检查和 claim 接受/拒绝数写入 QA 轨迹。
- Web 可通过环境变量选择检索模式与每题证据数，默认值仍保持 BM25、5 条证据。

P9-015 定向真实模型复核确认：先前 180 字符摘录上限截断了 `via online gradient descent`。提升到 260 字符后，模型回答保留了 online gradient descent，覆盖审查通过。

## P9 真实模型评测

最终运行使用 `hybrid_bge_wide`、每题最多 8 条证据，覆盖全部 30 题。模型作答 5/27 道可回答题；3 道不可回答题均正确拒答。按系统覆盖审查，有 3/27 道标为完整、2 道标为部分。逐条人工核查 5 个生成答案：4 个正确、1 个部分正确、0 个错误答案。P9-003 只答出 13 种生成方法，漏掉 29 个数据集；模型原答和引用保存在 `evals/p9-human-review-20261020.json`。

跨论文题 0/4 作答，冲突题 0/4，多跳题 0/4。22/27 可回答题仍拒答。轨迹归因：21 次发生在生成/审查阶段（16 次模型返回空 claims，5 次输出达到长度限制），1 次未组织出可用证据。最终 run 记录 9 个 claims，9 个通过支持/相关审查；没有 claim 被拒绝。P9-003 的缺项表明单靠模型 coverage 标记不足以证明答案完整，因此保留人工复核结果。

最终全量 run 54 次 API 请求，28,398 输入 tokens、5,615 输出 tokens、费用上界 `$0.0152574`。P9 全阶段累计账本为 `$0.21208680/$0.50`，未超用户批准的 `$0.50` 硬上限。
