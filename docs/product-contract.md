# PaperTrail 产品契约与阶段归属

## 最终使用效果

PaperTrail 面向毕设文献的阅读、比较与学习。最终交付应成为一个本机 Web 学习助手：

1. 用户可加载配置授权的毕设文献，也可上传个人 PDF；能查看文献身份、版本、索引状态和解析问题，并删除自己上传的来源。
2. 用户可围绕文献连续追问。回答展示每项结论的参考论文、文件版本、`PDF 第 N 页`、可核查短引文和检索相关性。相关性分数表示当前检索排序信号，不伪装成概率或事实可信度。
3. 用户可按概念写个人学习笔记，按关键词/概念检索和回顾笔记；笔记与对话历史属于个人学习记录，不能进入原论文证据池，也不能在引用卡片上冒充论文结论。
4. 用户可查看文献载入/解析/索引进度、问答次数、笔记数量和待处理解析问题，并导出包含学习摘要、问答及引用指针、笔记和进度的学习报告。
5. 多轮对话保留当前会话必要上下文。跨会话的问答回顾与个人笔记可检索，但必须与原文证据分开存储、检索和呈现。
6. 系统保留 PaperTrail 的差异化能力：跨目录文件去重、论文身份与文件版本分离、文献版本谱系候选、混合检索调试、逐 claim 引文核验，以及跨论文支持/反对/适用条件并列对照。证据不足时拒答或标明缺口。

## 证据与记忆边界

- **原文证据**：来自用户授权 PDF 的 `EvidenceSpan`，保存源文件 SHA-256、逻辑论文 ID、文件版本 ID、PDF 物理页码、块 ID、短引文和解析器版本。每个已证实的回答 claim 都需要程序校验过的原文指针。
- **阅读笔记**：来源类型标为 `reading_note`，可用于个人回顾或作为检索线索；不得代替或伪装成原论文证据。必须经原论文核实后，才可作为论文证据引用。
- **个人学习笔记**：独立的 `personal_note` 记录，具有用户/概念/时间/会话元数据；检索到笔记时在界面中明确标“个人笔记”，不进入证据账本。
- **对话记忆**：工作记忆只保留当前会话需要的最近上下文；跨会话的问答事件回顾属于学习历史。它们都不能提升为论文事实。
- OCR、生成式扩展查询、HyDE 假设答案等产物均是派生数据，不能作为原文证据；检索到真实文献页并校验后才可支持回答。

## 阶段归属与关口

| 阶段 | 交付边界 | 验收重点 |
|---|---|---|
| S0（已完成） | 只读资料盘点、SHA-256 去重线索、版本候选、人工黄金问题集、基线设计 | 每个源目录明确；原始 PDF 未变；黄金短引文可按页人工核验 |
| S1（已完成） | 解析文本型 PDF 与 Markdown；保留来源类型、标题/章节、PDF 页码和表格文本；章节父块/段落子块；SQLite FTS5 BM25；CLI `index/search/inspect` | 用 10–15 篇真实文献抽查；题名、DOI、术语和页码定位正确；同 SHA PDF 不重复显示；记录黄金题 Recall@5 基线。此阶段不做 Web UI、LLM 问答、向量索引或 OCR |
| S2（已完成） | 本地字符 TF-IDF 潜在向量检索；BM25/向量加权 RRF；按索引修订号自动失效重建；可选 Tesseract OCR 回退，OCR 来源单独标记 | 已在同一黄金集测 BM25、vector、hybrid 的 Recall@5/MRR/nDCG/查询耗时。候选向量与混合未胜过 BM25，因此保留为可选调试模式，不提升默认检索；MQE/HyDE 暂不引入，OCR 引擎未安装时清楚报错。任何付费 API 仍需事先批准 |
| S3（已完成） | 受检索证据约束的抽取式回答、结构化 claim、EvidenceSpan 校验和拒答；支持同一会话连续追问 | 逐 claim 引用判定；引用文件哈希、页码和原句一致；多轮上下文不会覆盖来源边界 |
| S4（已完成） | 跨论文并列证据、人工标注支持/反对/条件/背景、用户提出的研究空白候选 | 比较项至少来自多篇论文且每条有可校验页码；机器不臆测立场；人工标签、理由、空白候选与依据分别持久化 |
| S5（已完成） | 仅监听本机的 Web 界面；更新明确选择的授权文献、上传和删除个人 PDF；问答/历史、个人笔记/回顾、跨论文标注、进度和 JSON 学习报告导出 | 导入、检索、引用核验、记录和导出形成端到端闭环；个人笔记、问答历史、论文原文保持分开；用户上传删除只影响个人文件；服务不对局域网开放 |

### S2 候选技术评测约定

MQE 可能帮助术语和表达多样性；HyDE 可能帮助问题句与论文陈述之间的语义差异。它们会额外调用生成模型并可能引入错误查询，因此不按教程描述直接开启。S2 在黄金集中预先标出相应题型，比较基础检索与候选方案的 Recall@5/MRR、查询耗时、失败率和真实 token/费用；任何付费 API 评测须先说明模型、费用估计并取得用户许可。多层记忆也作为功能需求而非四套存储的强制设计：先实现会话工作上下文、独立个人笔记和可回顾学习事件，只有测得收益后才添加语义图或多模态记忆。

## S1 数据契约

- 同一 SHA-256 代表同一文件字节流：搜索结果只显示一次，但保留所有可追溯路径。
- 不同 SHA-256 代表不同 `PaperVersion`；DOI/题名相似只标为谱系候选，不能自动覆盖或合并。
- 关键词检索的 FTS 行对应可定位的段落子块，字段包括逻辑论文 ID、版本 SHA、来源类型、标题/章节、PDF 页码、短文本和父块 ID。页码始终是 PDF 物理页码。
- PDF 提取失败/扫描页需记录原因和页号。S1 不让空白页或阅读笔记伪装成可检索原论文内容。
- OCR 派生块始终标为 `ocr_derived`，仅作为检索线索；回答证据只能采用 native text 并按原 PDF 物理页复核。
- 数据库、提取全文和运行轨迹保存在 `.local/` 或 `indexes/`；Git 只提交代码、配置示例、短黄金引文和不含全文的学习文档。

## 参考体验

Datawhale《Hello-Agents》第八章 8.4 展示了 PDF 学习助手的 Web 操作闭环：加载文档、问答与相似度来源、个人概念笔记、学习回顾、进度统计和 JSON 报告。PaperTrail 借鉴其用户任务和学习闭环，不复制其源码、Gradio 页面或 Qdrant/Neo4j 组合；检索、版本谱系、原文证据和记忆边界按本项目的黄金集与本地文献重新设计。
