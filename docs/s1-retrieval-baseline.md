# S1 检索基线

## 语料与可复现设置

本次 S1 pilot 使用 15 个明确列入 `configs/s1-pilot.jsonl` 的源项：12 篇原文 PDF 和 3 篇中文阅读笔记。按 SHA-256 合并字节完全相同的 PDF；源文件只读。数据库和检索轨迹保存在 `.local/`，不提交。检索为 SQLite FTS5 `unicode61` 分词与 BM25 排序，先用正文 AND 匹配，必要时放宽到正文 OR；DOI 可精确匹配。题名和章节保留用于展示及无正文命中时的后备搜索。查询不调用生成模型或外部 API。

黄金集共有 34 题，其中 31 题可回答、3 题应拒答。以每个可回答问题人工标注的目标 PDF 页作为命中条件，top-5 结果中至少出现一个目标证据页计为 page Recall@5；目标论文任意页面命中计为 document Recall@5。脚本输出逐题轨迹便于复核：`python -m papertrail.evaluate --db .local/papertrail-s1-final.sqlite3 --gold evals/gold.jsonl --k 5 --trace-out .local/s1-final-trace.json`。

## 结果

| 指标 | 命中 | 比率 |
|---|---:|---:|
| 目标论文 Recall@5 | 28/31 | 90.3% |
| 目标证据页 Recall@5 | 10/31 | 32.3% |
| 全部标注证据页均命中 | 8/31 | 25.8% |

目前基线的论文级召回较高，页级定位明显不足。中文问题与英文原文的词汇差异、短查询中的术语多义、同一术语在相关论文中的重复，以及 PDF 版式噪声都会造成错页或错文献。重复页眉/页脚已按跨页重复块过滤；题名候选复用 S0 过滤规则，避免把会议横幅误当论文标题。上述处理改善索引质量，但纯词法 FTS 并不理解语义，也没有证明表格内容已结构化。

该结果仅是 12 篇 PDF pilot 和当前黄金集的本地基线，不代表完整语料或问答准确度。下一阶段应保留同一黄金集比较 BM25、dense 与 hybrid，按题型报告 Recall@5、MRR、nDCG、耗时及索引成本，并抽查具体证据；MQE/HyDE 只作为待评候选，不作为证据来源。
